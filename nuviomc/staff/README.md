# NuvioMC — מועמדות לצוות

ערכה מלאה לפתיחת מועמדויות: טופס, דרישות, שיטת ניקוד, תבניות תשובה והגדרת דיסקורד.
הכל אפשר להפעיל מהטלפון או מהדפדפן — אין צורך בגישה לשרת.

## קבצים

| קובץ | מה זה |
|------|-------|
| `application-form.md` | שאלות הטופס, מוכן להעתקה ל-Google Forms או לפורום דיסקורד |
| `review-guide.md` | דרישות סף, שיטת ניקוד, ודגלים אדומים |
| `response-templates.md` | תבניות תשובה: קבלה, דחייה, סיום טריאל |
| `discord-setup.md` | ערוצים, רולים והרשאות בדיסקורד |

## סדר פעולות

**לפני שפותחים — חובה:** להריץ את `permissions/` עד הסוף.
פתיחת מועמדויות לפני שעץ ההרשאות מסודר פירושה לתת גישות לאנשים חדשים
בזמן שאתה עצמך לא יודע בדיוק מה כל דרגה יכולה לעשות. זה הסדר ההפוך.

1. להריץ `permissions/01` עד `04`, כולל שלב ה-OP.
2. להקים את ערוצי הדיסקורד לפי `discord-setup.md`.
3. לפרסם את הודעת הפתיחה (ב-`response-templates.md`).
4. להשאיר פתוח 7–10 ימים, ואז לסגור. חלון סגור מייצר יותר הגשות איכותיות מחלון שפתוח תמיד.
5. לסנן לפי `review-guide.md`.
6. לראיין את מי שעבר — 10–15 דקות בקול.
7. לקבל כ-`trial` לשבועיים, עם `parent addtemp` כדי שהדרגה תפוג מעצמה.
8. בסוף השבועיים: קידום ל-`helper`, הארכה, או סיום.

## כמה אנשים לקחת

תלוי בכמה שחקנים יש במקביל בשיא. הכלל המקובל הוא בערך איש צוות אחד
פעיל לכל 15–20 שחקנים בו־זמנית.

צוות גדול מדי הוא לא "יותר כיסוי" — זה יותר אנשים עם גישות שאתה לא
עוקב אחריהן, ופחות תחושת אחריות אצל כל אחד מהם. עדיף לקחת שלושה טובים
מאשר שמונה בינוניים.

## למה טריאל זמני, ולא קבוע

```
lp user <שם> parent addtemp trial 14d
```

הדרגה פגה לבד אחרי שבועיים. אין שיחה מביכה, אין "שכחתי להוריד אותו",
ואין אנשים שנשארים עם גישות חודשים אחרי שהפסיקו להיכנס.
אם החניך טוב — אתה מקדם אותו באופן פעיל. זו החלטה, לא ברירת מחדל.
